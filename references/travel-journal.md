# 批量照片电子手帐

## 交付约定

用户给出照片文件夹或附件后，自动完成整理、选片、章节、文案、排版和检查。除旅行事实存在关键冲突外，不逐页要求确认。未指定时使用中文、奶油纸色与墨蓝标题，输出单文件、无外部依赖的 `journal.html`。用户要求 PDF、特定页数或手机比例时优先遵从。

体验目标是让用户愿意展示自己的旅行：封面优先选择最有视觉吸引力且能代表旅程的真实照片，短标题突出这段旅程的独特之处；正文有大小节奏和足够留白。用户是主角，不给每一页叠加抢眼的 Skill 品牌，不添加夸大经历的文案。

原图只读。所有整理和排版在独立输出目录进行，不把照片放进 Skill 仓库。附件尚未落盘时先用宿主提供的附件路径；不能访问时请用户提供照片或路径，不把“等待素材”说成已完成。几十张图不用一次塞进图像生成器。

## 1. 建立照片清单

用可用的 Python 运行以下命令（需要 Pillow）。`SKILL_DIR` 为此 Skill 的实际目录；`PHOTO_DIR` 为用户照片目录；`RUN_DIR` 为新的输出目录，放在照片目录之外。

```bash
python3 "$SKILL_DIR/scripts/prepare_photos.py" "$PHOTO_DIR" "$RUN_DIR"
```

工具会递归读取常见图片，生成 `manifest.json`、去除 EXIF 的阅读副本 `photos/`、以及每页最多 20 张的编号预览 `contacts/`。完全相同的文件按 SHA-256 标记为重复；近似重复仍需人工视觉判断。EXIF 拍摄时间仅作为排序线索，不把文件修改时间当旅行日期。时间无时区或多台相机时间不一致时，以用户提供的信息校正；不要在证据不足时标注“第几天”。

逐页查看全部编号预览，并打开入选主图、人物较小或细节不清的原图核对。清单不是视觉理解：不能只读文件名或 EXIF 就声称看完照片。损坏或暂不支持的格式会记录在清单中；对 HEIC 等先使用环境中可用的解码器转换副本，再补入清单，或明确报告未处理数量，不静默丢失。

## 2. 选片与叙事

在清单中给每张可用图记录可见内容、选择状态及理由。默认精选代表性照片，完全重复图只用一次；不要把略模糊但承载重要回忆的图一律淘汰。用户要求全部使用时，除损坏文件外纳入所有图，重复图也可进附录，并明确说明。

有可靠日期且用户要求按时间叙述时按天分章；否则按已知地点或可见场景分章，如“沿街散步”“餐桌上的片刻”“海边停留”。不能把视觉相似误当同一地点。不得推断人物姓名、关系、情绪、行程先后或未提供的内心感受。可以使用有具体观察的文学旁注，按 [写作标准](writing.md) 区分主题比喻与事实；用户原话可作日记引语。精确位置、日期和路线没有证据就省略。

一般每个内容页 1–4 张照片，结合封面、章节页及收尾，页数随素材变化。30–60 张原片不等于必须全部使用或固定 20 页。封面大图、双图对照、三四图细节页交替出现；避免所有页面都是等大九宫格。每段文字具体且有长短变化，不写泛泛的“治愈了灵魂”。

默认拼贴手帐完成选片后，返回 [拼贴手帐制作](scrapbook.md) 进行艺术排版和同源导出。以下相册流程仅适用于用户明确要求摄影相册。

## 3. 备选摄影相册：编排与生成

写入 `journal-plan.json`，使用预览图上的稳定编号：

```json
{
  "title": "沿途的小事",
  "subtitle": "一次旅行的纸上记录",
  "cover_photo_id": "P0001",
  "pages": [
    {
      "title": "雨停以后",
      "text": "石板上还留着水光。",
      "photos": [
        {"id": "P0002", "caption": "湿润的街巷"},
        {"id": "P0003", "caption": "窗边的茶杯"}
      ]
    }
  ]
}
```

这些句子只是格式示例，实际必须与已查看的照片或用户叙述相符。每页 1–4 张；需要更多图就加页。避免正文堆积：标题约 20 字以内，正文约 100 字以内，图注约 30 字以内。封面图可在正文再次出现；正文重复使用必须有叙事理由。

```bash
python3 "$SKILL_DIR/scripts/build_journal.py" "$RUN_DIR/manifest.json" \
  "$RUN_DIR/journal-plan.json" "$RUN_DIR/journal.html"
```

生成器内嵌去除 EXIF 的照片，保留完整画幅，使用真实可选择的文字、目录锚点和打印样式。若用户需要更强的定制美术，可在成稿上调整 HTML/CSS，仍保持离线自包含和照片完整性。默认的纸张、边框与胶带可以由 CSS 绘制；不需要为了装饰而强制调用图像工具。需要独特贴纸时回到主 Skill 的贴纸流程，生成后嵌入，不替换照片主体。

离线 HTML 在不同手机文件查看器中体验可能不同，交付时说明用浏览器打开；不要承诺所有应用都能直接预览。大文件需报告体积，按实际需要降低阅读副本尺寸或拆分册，不改变原图。

## 分享网站与社交图片

生成器提供分享入口和 1080 × 1440 的 PNG 导出：封面单独生成，整套内容页批量生成后可逐张保存。图片使用同一组真实照片和文字重新排版，照片完整显示、无网页导航与按钮。默认 3:4 竖图适合本项目的社交展示需求，不将其宣称为微信或小红书唯一尺寸规范。

实际点击封面与整套图片导出；核对下载文件的尺寸、文字、照片和页序。用户要直接得到图片文件时，优先下载整套 ZIP 并验证文件数量与可解压性，再保存所有成品至 `social/` 后交付，不能只给一个从未点击过的按钮。移动端保留逐张保存与长按保存提示，整套 ZIP 避免浏览器连续下载限制。

分享整本需要真实可访问的网站。没有明确发布授权时，先做好本地成稿与发布包，再问要部署到哪个已配置的平台。用户已授权指定目标时不重复确认。使用环境可用的静态托管能力，部署后核对公网访问、手机阅读、分享按钮和图片导出；最终提供实际网址。线上分享默认不调用社交平台发帖接口。

公开前选片时排除敏感证件和未授权公开照片，阅读副本去除 EXIF。若用户需要私密链接，选用实际支持访问控制的托管方案；随机路径或不被搜索收录不等于私密。社交应用的链接预览卡片需要额外的公开封面 URL 与元数据，应在部署时配置并测试；离线单文件不承诺微信自动生成封面预览。

## 4. 检查与交付

- 对照清单：输入数、可用数、完全重复数、错误数、入选数和未选理由可追溯；明确未处理的图片。
- 浏览器打开最终 HTML，查看封面、所有正文页和收尾；检查手机宽度、中文换行、图注、人物完整性、导航和离线图片加载。长内容不能溢出或被裁掉。
- 要 PDF 时，用环境已有浏览器打印能力或 PDF 工具导出，核对纸张大小、分页及中文字体，并将 PDF 全页渲染检查。没有导出能力就说明只交付 HTML，不把打印样式称为 PDF 文件。
- 输入照片的 EXIF 已去除不代表画面内没有隐私。发现证件、订单号、二维码和住址等可见敏感信息时，选择其他图或制作遮挡副本；不得覆盖原图。当地标身份不确定时用通用图注。
- 面向客户的最终文件是 `journal.html` 及实际生成的 PDF。清单、阅读副本与计划留在本地用于修改，不附带原始路径清单向外分享。交付不等于上传网站或发布照片。

说明使用了多少张照片、生成多少个内容页、实际输出格式，以及未完成的检查。没有真实旅行照片时可以做明确标注的合成样本验证工具，但不能据此宣称真实选片质量或人物保真已验收。
