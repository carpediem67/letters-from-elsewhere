# 拼贴手帐：默认电子手帐方向

电子手帐的核心是把旅途变成纸上记忆。先设计纸页，再装进翻阅网站。不能把等宽照片卡片加上标题当作已完成的手帐。

排版前读取 [手作视觉标准](visual-standard.md)，将用户参考的具体特征写进本次构图记录。扩页沿用已确认的纸本阅读形式，重新检查全本节奏；不要只复制旧页模板或切回素材画廊。

## 素材与构图

1. 查看原照片，按场景与细节分组。照片保持原图；允许裁切，但检查人物和地标主体。不要让生成图替换用户的真实经历。
2. 按照片内容生成专属地标、食物、衣物等贴纸，检查透明通道。人物贴纸若经生成重绘，明确它是插画，不声称是原图精确抠图。需要保留人物时必须传入参考照片。
3. 每页先定主视觉：撕边风景、剪影地标、票据叠层、路线旁注、开窗纸片等。每页采用不同大小、方向与叠放顺序；贴纸参与叙事，不能只在卡片角落贴通用图标。
4. 使用纸纹、细碎不规则撕边、少量胶带、影子、手写短句和圈线。避免整齐网格、统一标题栏、所有照片同尺寸、巨大的规则锯齿纸边。
5. 日期、票号、价格、人物关系只用已提供的信息。装饰票据使用主题文字，不伪造消费记录。合成测试照片需标识。

## 制作与导出

- 建议每页 3:4，排版源稿 600×800 CSS px，导出至少 1080×1440 PNG，也可按两倍像素导出 1200×1600。
- 使用 HTML/CSS/SVG 放置原照片、透明贴纸和真实可读文字。字体采用允许使用和分发的字体，附授权。文字不可依赖图像模型生成。
- 保留 `composition.html` 或等价可编辑排版源稿；在真实浏览器加载字体、等待图片解码后截取每一页。不要另写一套简化 Canvas 布局来导出。
- 查看所有导出页，检查文字遮挡、主体裁切、层次、纸边和字体，再将 PNG 交给翻阅器：

```bash
python3 scripts/build_scrapbook.py ./pages --output ./journal.html --title '我的旅行剪贴簿'
```

翻阅器包含图片，离线可打开；电脑双页、手机单页；方向键、滑动和按钮翻页，下载当前页或整套 ZIP。显示与导出使用同一 PNG。网页文字在页面图像中已栅格化；需要修改内容应回到排版源稿。大批照片应精选分页，避免单文件过大。

## 验收

- 全部照片有用途记录，重复使用有构图理由；不声称未用照片已经进入手帐。
- 导出 PNG 的尺寸和数量正确；ZIP 可解压且与页面一致。
- 电脑、手机都实际检查翻页、下载、文字和图片加载。
- 本地网址不能供别人访问。公开部署需确认具体发布范围；部署后可分享整个网址。不能把本地预览叫作已上线。
- 视觉验收由用户判断；技术通过不能替代“像参考图的手帐”。

若用户明确要摄影相册而非拼贴手帐，才使用 `build_journal.py` 的照片分章布局。

## 用于 Skill 展示的样册

展示样册先确定作品的叙事与视觉语言，再为合适的场景安排能力示例、选择照片。不要用同一套“大图＋小图＋一句话”重复整本，也不要把照片质量当作手帐质量的替代品。

- 让单枚贴纸、独立贴纸页、照片转插画、纸片叠层、开窗、票据、手写旁注、路线叙事等能力各有可见示例；按已有素材选用，不强行塞满所有页面。
- 手帐是成品主体；原图与能力对照放在单独的展示入口。照片参与纸页构图，贴纸跨越纸片边缘或呼应具体场景，避免只在角落充当图标。
- 真实感优先使用用户提供的照片；示范素材可使用已逐张核实许可的公开摄影。保存作者、照片详情页、下载来源、许可链接和页面用途。免费商用不等于归本项目 MIT 授权，也不意味着人物为产品代言。
- 公开照片与主题创作文案组成的示范本，标明是素材演示，不包装成同一位用户的真实旅行记录。装饰票据不冒充真实订单，路线索引不冒充精确导航。
- 展示“照片转插画”时传入原图并保留前后对照；插画重绘与精确抠图区分说明。没有实现或验证的能力不写成已支持。
- 先检查缩略总览的构图差异，再逐页检查主体、断行、遮挡和纸边；最后检查网页与导出文件。技术验证不能替代用户的视觉验收。

用户要求艺术感的展示样册时，使用 [艺术家采集簿方向](art-direction.md#艺术家采集簿)；让能力服务作品的构图与叙事。
